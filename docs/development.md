# Локальная разработка

Нужны Docker Compose, Node.js 18+ с npm и Make. Для SCSS используется Sass;
версия зафиксирована в `package.json` и `package-lock.json`.

При первом запуске скопируйте `.env.example` в `.env` и задайте
`MYSQL_PASSWORD` и `MYSQL_ROOT_PASSWORD`. Затем:

```sh
make setup
```

Команда запускает Compose, устанавливает Composer/npm-зависимости, собирает CSS,
применяет миграции и добавляет демоданные. Отдельные шаги можно выполнить командами
`make up`, `make install`, `make build`, `make migrate`, `make seed`.

Сайт: http://localhost:8080. Порт можно изменить через `HTTP_PORT` в `.env`.

## Стили и изменения PHP

`make build` (или `npm run build`) собирает `scss/app.scss`
в читаемый `public/assets/app.css` без сжатия. Готовый CSS храним в репозитории, чтобы для просмотра
сайта не требовался Node.js.

Для работы со стилями запустите в отдельном терминале:

```sh
make dev
```

Это `npm run dev`: Sass следит за SCSS и пересобирает CSS после изменений.
Остановить наблюдение можно через Ctrl+C. Перед коммитом выполните `make build`.

PHP-код и шаблоны доступны контейнерам через bind mount. Для обычных изменений
PHP, классов и Smarty-шаблонов достаточно обновить страницу в браузере.
Автоматической перезагрузки вкладки нет. Новые классы в `src/` подхватит
Composer через настроенный PSR-4 autoload.

При изменении Dockerfile выполните `make up`, чтобы пересобрать образ.
После изменения зависимостей Composer выполните `make install`.
После изменения `package.json` выполните `npm install` и сохраните lock-файл.

## Остальные команды

- `make migrate` — применить SQL-миграции к основной локальной БД.
- `make seed` — добавить 12 статей и 4 категории, только если БД пустая. Повторный запуск ничего не меняет.
- `make test` — проверить БД, главную, сиды и HTTP на отдельных `php_test`, `nginx_test` и `mysql_test`.
- `make stop` — остановить сервисы, сохранив данные MySQL.

Структура БД описана в [database/README.md](../database/README.md).

## Главная и темы

Главная работает через `HomeController`, `HomeService`, `CategoryRepository`
и `ArticleRepository`. Сервис собирает категории с тремя последними статьями.
SQL остаётся в репозиториях; Smarty получает готовые массивы.
Выборка использует оконную функцию MySQL 8, поэтому число запросов не растёт
вместе с количеством категорий. При совпадении дат сначала идёт больший ID.

Кнопка в шапке переключает светлую и тёмную тему. Выбор хранится в `sessionStorage`
для текущей вкладки и сохраняется при обновлении страницы. Без JavaScript доступна
светлая тема. Если хранилище недоступно, переключение работает до обновления страницы.

Пока реализована главная. Ссылки на категорию и статью подготовлены для следующих
этапов; сейчас эти страницы возвращают 404.

Тестовые HTTP-запросы идут через отдельный nginx к тестовому PHP и временной MySQL.
`tests/database.php` перед каждым запуском очищает только `mysql_test/blog_test`.
Для остановки тестового окружения без изменения рабочей БД:

```sh
docker compose -f compose.yaml -f docker-compose.test.yml stop nginx_test php_test mysql_test
```

## Дальнейшие этапы

Следом добавим страницы категории и статьи. Затем — пользователей,
регистрацию по логину, имени и паролю, вход и комментарии.
Читать статьи можно будет без регистрации, комментировать — после входа.

Отдельный этап — кабинет автора и админка: создание и редактирование статей,
загрузка изображений, простой редактор, профиль автора со списком его статей.
Обычный пользователь сможет комментировать; автор — управлять своими статьями;
администратор — управлять всеми статьями и назначать роли.
Новые пользователи будут получать обычную роль. Проверки прав будут на сервере.
В админке также нужна генерация 50–100 демонстрационных статей и комментариев.
Формы получат CSRF-защиту и серверную валидацию; пароли будем хранить в виде хешей,
SQL выполнять через prepared statements, а загружаемые изображения проверять.
