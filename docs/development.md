# Локальная разработка

Нужны Docker Compose, Node.js 18+ с npm и Make. Для SCSS используется Sass;
версия зафиксирована в `package.json` и `package-lock.json`.

При первом запуске скопируйте `.env.example` в `.env` и задайте
`MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD` и три `SEED_*_PASSWORD`, описанные ниже. Затем:

```sh
make setup
```

Команда запускает Compose, устанавливает Composer/npm-зависимости, собирает CSS,
применяет миграции и добавляет демоданные. Отдельные шаги можно выполнить командами
`make up`, `make install`, `make build`, `make migrate`, `make seed`.

Сайт: http://localhost:8080. Порт можно изменить через `HTTP_PORT` в `.env`.

## Стили и изменения PHP

`make build` (или `npm run build`) собирает `scss/app.scss`
в читаемый `public/assets/app.css` без сжатия. Готовый CSS храним в репозитории, чтобы для просмотра
сайта не требовался Node.js.

Для работы со стилями запустите в отдельном терминале:

```sh
make dev
```

Это `npm run dev`: Sass следит за SCSS и пересобирает CSS после изменений.
Остановить наблюдение можно через Ctrl+C. Перед коммитом выполните `make build`.

PHP-код и шаблоны доступны контейнерам через bind mount. Для обычных изменений
PHP, классов и Smarty-шаблонов достаточно обновить страницу в браузере.
Автоматической перезагрузки вкладки нет. Новые классы в `src/` подхватит
Composer через настроенный PSR-4 autoload.

При изменении Dockerfile выполните `make up`, чтобы пересобрать образ.
После изменения зависимостей Composer выполните `make install`.
После изменения `package.json` выполните `npm install` и сохраните lock-файл.

## Остальные команды

- `make migrate` — применить SQL-миграции к основной локальной БД.
- `make seed` — добавить демо-аккаунты, статьи в пустую БД и первые комментарии. Существующие пароли и статьи сохраняются.
- `make test` — проверить БД, главную, сиды и HTTP на отдельных `php_test`, `nginx_test` и `mysql_test`.
- `make stop` — остановить сервисы, сохранив данные MySQL.

Структура БД описана в [database/README.md](../database/README.md).

## Главная и темы

Главная работает через `HomeController`, `HomeService`, `CategoryRepository`
и `ArticleRepository`. Сервис собирает категории с тремя последними статьями.
SQL остаётся в репозиториях; Smarty получает готовые массивы.
Текущий пользователь передаётся контроллерам как `App\Model\User`.
`BaseController` содержит только рендер, перенаправление и доступ к пользователю.
Сборка зависимостей находится в `config/controllers.php`; контейнера зависимостей нет.
Ошибки запроса передаются через `HttpException` и обрабатываются в `public/index.php`.
Ошибки форм используют `ValidationException` и возвращают форму со статусом 422.
Выборка использует оконную функцию MySQL 8, поэтому число запросов не растёт
вместе с количеством категорий. При совпадении дат сначала идёт больший ID.

Кнопка в шапке переключает светлую и тёмную тему. Выбор хранится в `sessionStorage`
для текущей вкладки и сохраняется при обновлении страницы. Без JavaScript доступна
светлая тема. Если хранилище недоступно, переключение работает до обновления страницы.

Тестовые HTTP-запросы идут через отдельный nginx к тестовому PHP и временной MySQL.
`tests/database.php` перед каждым запуском очищает только `mysql_test/blog_test`.
Для остановки тестового окружения без изменения рабочей БД:

```sh
docker compose -f compose.yaml -f docker-compose.test.yml stop nginx_test php_test mysql_test
```

## Аккаунты, публикации и комментарии

Перед `make setup` задайте в локальном `.env` три пароля длиной 8–72 байта:
`SEED_ADMIN_PASSWORD`, `SEED_WRITER_PASSWORD`, `SEED_READER_PASSWORD`.
Сидер создаёт `admin` (администратор), `writer` (автор) и `reader` (читатель).
Пароли хешируются в PHP. Повторный сид не меняет существующие пароли и статьи.
Если база уже заполнена, достаточно `make migrate` и `make seed` после обновления
PHP-контейнера командой `make up`.

Миграция `002_add_users_and_comments.sql` добавляет роли, пользователей, автора
статьи и отдельную таблицу комментариев. Сидер назначает старые статьи пользователю
`writer` и добавляет два комментария к первой статье. Автор пока допускает NULL
для безопасного обновления базы; форма публикации всегда записывает ID из сессии.

Чтение доступно без аккаунта. `/register` создаёт читателя; `/login` открывает вход.
Администратор назначает роли на `/admin/users`. Автор создаёт статьи на
`/article/new`, меняет и удаляет свои публикации со страницы статьи. Администратор
может управлять всеми статьями. Профиль `/profile?id=…` доступен без входа.

Обложка — JPEG, PNG или WebP до 2 МБ и 20 мегапикселей. Файл хранится в Docker-томе
`uploads`, в MySQL записывается путь. Исходное имя файла не используется.
Редактор принимает обычный текст, без HTML. Комментарии доступны после входа,
ограничены 2000 символами и выводятся с экранированием. В обсуждении 10 комментариев
на страницу, в категории и профиле — 6 статей. Категория поддерживает `sort=date`
и `sort=views`; пагинация сохраняет сортировку. Похожие статьи выбираются по числу
общих категорий, затем по дате публикации и ID, максимум три.

`make test` проверяет миграции, сид, главную, доступы, SQL-сортировку и HTTP-сценарий
с настоящей загрузкой изображения. Используются отдельные MySQL и том `uploads_test`.
Счётчик осмысленного просмотра и генератор 50–100 статей через админку ещё не добавлены.

## Фильтры статей

`/articles` — общий список с поиском по заголовку, категории, началу ника автора
и датам публикации. Параметры: `q`, `category`, `author`, `from`, `to`, `sort`, `page`.
Даты задаются как `2026-01-10`, обе границы включаются целиком. Без фильтра показываются
все статьи; при новом применении фильтра открывается первая страница.
Сброс возвращает к общему списку. Ссылки пагинации сохраняют все выбранные параметры.

Контроллер преобразует запрос в `ArticleFilter`, сервис считает страницы,
репозиторий использует одинаковые условия для списка и COUNT. Поиск по заголовку
ищет буквальное вхождение: `%` и `_` не становятся пользовательскими SQL-шаблонами.
Форма находится в `templates/partials/article-filters.tpl`, AJAX пока не нужен.
