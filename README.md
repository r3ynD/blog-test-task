# Блог на PHP и Smarty

Тестовое задание: небольшой блог с категориями, публикациями и комментариями.
Читать статьи можно без регистрации. Аккаунт нужен для комментариев, а роль автора —
для публикации своих статей.

PHP 8.1+, Smarty 5, MySQL 8, обычный JavaScript и SCSS. Без PHP-фреймворка и ORM.
В Docker используются PHP 8.4 FPM, nginx и MySQL 8.4.

## Запуск

Нужны Docker Compose, Make и Node.js 18+ с npm. PHP и Composer на хосте не нужны.

```sh
cp .env.example .env
```

В `.env` задайте `MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD` и пароли демо-аккаунтов:
`SEED_ADMIN_PASSWORD`, `SEED_WRITER_PASSWORD`, `SEED_READER_PASSWORD`.
Пароли аккаунтов — от 8 до 72 байт. Остальные настройки можно оставить как есть:
`HTTP_PORT=8080`, `MYSQL_DATABASE=blog`, `MYSQL_USER=blog`.
`.env` не хранится в Git.

```sh
make setup
```

Команда соберёт и запустит контейнеры, установит Composer/npm-зависимости,
соберёт CSS, применит миграции и добавит демоданные.
Открыть сайт: **http://localhost:8080**.

## Демо-аккаунты

| Логин | Роль | Возможности |
| --- | --- | --- |
| `admin` | Администратор | Все статьи и управление ролями |
| `writer` | Автор | Свои статьи и комментарии |
| `reader` | Читатель | Комментарии |

Пароли берутся из соответствующих `SEED_*_PASSWORD` в `.env`, в базе сохраняются хеши.
Сидер добавляет 4 категории, 12 статей и 2 комментария. Повторный запуск сохраняет
существующие статьи, пароли и роли. Старым статьям без автора назначается `writer`.
Новая регистрация всегда создаёт читателя; роль автора выдаёт администратор.

## Что работает

- Главная `/`: категории с тремя последними статьями. Пустые категории не выводятся.
- Архив `/articles`: поиск по заголовку, категории, началу ника автора и периоду
  публикации. Даты включаются целиком. Сортировка — новые или популярные.
- Категория `/category?id=1`: сортировка по дате или просмотрам, пагинация.
- Статья `/article?id=1`: обложка, текст, категории, автор, дата, просмотры,
  похожие статьи и комментарии.
- Профиль `/profile?id=1`: информация о пользователе и его публикации.
- `/register`, `/login`: регистрация и вход. Email не требуется.
- `/article/new`: публикация статьи. Редактирование и удаление доступны со страницы
  статьи: автору своей публикации и администратору.
- `/admin/users`: назначение ролей. Последнего администратора нельзя понизить.

В архиве, категории и профиле по 6 статей на странице; комментарии и пользователи —
по 10. Фильтры передаются через GET, сохраняются в ссылках пагинации и применяются
с обычной загрузкой страницы. Похожие статьи выбираются по числу общих категорий,
затем по дате публикации и ID; текущая статья исключается, результат ограничен тремя.

Редактор принимает обычный текст с абзацами. Обложки: JPEG, PNG или WebP до 2 МБ
и 20 мегапикселей. Файлы находятся в Docker-томе `uploads`, в БД хранится путь.
Комментарии — обычный текст до 2000 символов. Вывод экранируется Smarty;
формы защищены CSRF, SQL выполняется через PDO с подготовленными запросами.

Светлая и тёмная темы переключаются в шапке. Выбор сохраняется в текущей вкладке.

## Команды

```sh
make up       # Собрать и запустить окружение
make migrate  # Применить новые SQL-миграции
make seed     # Добавить демоданные
make build    # Собрать SCSS в public/assets/app.css
make dev      # Следить за SCSS и пересобирать CSS
make test     # Проверки на отдельной тестовой MySQL
make stop     # Остановить окружение, сохранив данные
```

Для установки зависимостей отдельно: `make install`. PHP и Smarty подхватывают
изменения при обновлении страницы; перезапуск контейнеров не нужен.
CSS хранится в репозитории в читаемом виде, без минификации.

Тесты проверяют миграции, сиды, выборки, фильтры, пагинацию, права и HTTP-сценарий
с загрузкой обложки, публикацией и комментариями. Тестовые данные находятся
в `mysql_test/blog_test` и отдельном томе `uploads_test`.
После изменения Dockerfile перед тестами пересоберите тестовые образы:

```sh
docker compose -f compose.yaml -f docker-compose.test.yml build test php_test
```

## Структура

```text
public/               Front controller и готовые статические файлы
src/Controller/       HTTP, формы и выбор шаблона
src/Service/          Логика страниц и публикаций
src/Repository/       SQL-запросы через PDO
src/Dto/, src/Model/  Параметры фильтра и текущий пользователь
templates/            Smarty-шаблоны
database/             SQL-миграции, схема и демо-контент
bin/                  Запуск миграций и сидера
scss/, tests/         Исходные стили и проверки
```

Зависимости собираются явно в `config/controllers.php`. В `BaseController` только
общий рендер, перенаправление и доступ к пользователю. Статья и её категории
сохраняются одной транзакцией. Роль загружается из базы на каждом запросе,
поэтому изменение прав не требует повторного входа.

Подробности схемы — в [database/README.md](database/README.md),
локальной разработки — в [docs/development.md](docs/development.md).

## Что осталось

Счётчик по времени чтения пока не подключён: отображается значение из БД,
демоданные содержат готовые числа просмотров. Генератора 50–100 статей в админке
пока нет. `author_id` допускает NULL для обновления старой базы; новые статьи
всегда получают автора из сессии. Публичное развёртывание с HTTPS отдельно не настроено.

## AI usage

ИИ использовался для подготовки демоданных, базовой вёрстки, обсуждения структуры
данных и перевода схемы БД из описания разработчика в миграции.
